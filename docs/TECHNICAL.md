# 기술 문서

## ROM 구조
- 게임 데이터는 ROM 안의 파일 테이블(Nisitenma-Ichigo 형식)로 묶여 있고, 많은 파일이 LZKN 계열 압축입니다(`tools/nisi.py`, `tools/lzkn.py`).
- 대사는 16비트 코드 스크립트입니다. 제어 코드(줄바꿈·버튼 대기·창·색 등)는 `tools/scen.py` 의 `CTRL` 표, 원본 글자표는 `tools/table.py`.
- 메인 코드와 오버레이에 일부 문자열이 직접 들어 있어 따로 뽑아 고칩니다(`tools/ovlx.py`, `tools/mips.py`).

## 한글 글꼴과 글리프 캐시
- 원본 글꼴은 RAM 0x80062BC0의 16×16 4bpp 타일(타일당 128바이트)이고, 한자 등 0x100 이후 코드도 같은 표를 씁니다.
- 한글 코드는 0x200부터 배정하고, 한글 글리프는 ROM 0xFA0000 이후(파일 영역 뒤)에 크기별 뱅크 3개로 둡니다.
  - 뱅크1: 본문 16×16, 뱅크2: 중간 크기(8×10), 뱅크3: 아주 작은 글자(7×8, 갈무리7 1:1)
- 글자 출력 루틴 두 곳(0x80010A2C, 0x8000CE28)을 헬퍼로 돌려, 한글이면 쓰지 않는 원본 타일 슬롯(LRU, 약 120개)에 PI DMA 대신 카트리지 직접 읽기로 128바이트를 복사합니다(`tools/cache.py`). 폭 레지스터로 뱅크를 고르고, 태그에 뱅크 비트를 넣어 같은 글자의 크기별 사본을 구분합니다.
- 코드가 글자 코드를 직접 넘기는 타일(「術」 0x110 → 타일 0x88, 「両」 0xEC → 타일 0x76)은 캐시 슬롯에서 빼고 「기술」「냥」 그림으로 바꿨습니다.

## 그림 글자
- UI 텍스처는 PIC 형식(팔레트·RLE)입니다. `tools/picdec.py`/`tools/picenc.py` 로 풀고 다시 넣으며, 컨테이너 오프셋을 다시 계산합니다.
- 한글 그림은 원본 텍스처의 글자 상자에 맞춰 그리고 원래 팔레트·그라데이션을 따릅니다(`tools/texko.py`).

## 레이아웃
- 한 줄 칸 수는 원문 + 2칸, 최대 20칸으로 제한하고, 상점 목록처럼 창 폭이 꼭 맞는 줄은 원문과 같은 칸 수로 맞췄습니다.
